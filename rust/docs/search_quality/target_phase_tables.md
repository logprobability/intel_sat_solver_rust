The conflicts, decisions and restarts are cumulative over the queries of an instance. The status of a recorded planner instance is that of its last query.

The configurations:

* `base`: the defaults (the mode 0: a numeric restart every 1000 conflicts)
* `target`: `/phase/target/on 1`
* `rephase`: `/phase/rephase/conf_init 1000` (`conf_incr 1000`: after 1000, 3000, 6000, ... conflicts)
* `t+r1000`: both: the schedule of CaDiCaL
* `t+r300`: both, `conf_init 300 conf_incr 300`
* `t+r100`: both, `conf_init 100 conf_incr 100`
* `t+r1000x1.5`: both, geometric: `conf_init 1000 conf_incr 0 conf_mult 1.5`
* `t+r1000rnd`: both, `/phase/rephase/random 1`: random phases instead of the flipped ones
* `flip1000`: the control, a perturbation without information: `/decision/polarity/flip_factor 1000` (the C++ solver's own parameter: every 1000th polarity selection is flipped)
* `m1`: `/mode/value 1`, whose restarts are LBD-based: the baseline of the next three
* `m1:t+r1000`: the mode 1 with both
* `m1:t2+r1000`: the mode 1 with `/phase/target/on 2`: no target phases under LBD-based restarts, so rephasing to the best phases only
* `m1:t+r300`: the mode 1 with both, `conf_init 300 conf_incr 300`
